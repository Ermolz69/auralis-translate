# Implementation status and evidence

Status: 25 September 2026. This log reports observed behavior, not release claims. Strict plain-SRT inspection and manual replacement work. A real model has produced a separate Russian SRT through both the experimental path and the durable CLI. Translate SQLite stores run attempts, accepted checkpoints, and immutable results. CLI tests cover managed-source copying, model failure, restart, completion, and reconstruction against a mock HTTP model server for SRT and WebVTT. A real-model SRT result was re-exported after server shutdown. An opt-in real-model Auralis application test kills the managed worker after one checkpoint, recovers both databases, and resumes the remaining block. A separate [native Tauri checked-model test](../eval/experiments/2026-09-25-native-tauri-translation.md) now verifies desktop invocation and separate ready output publication. Whole-desktop crash/restart and release validation remain open.

The [open-data evaluation protocol](evaluation/001-open-data-and-language-gates.md) now lists candidate data and a provenance/review procedure. No third-party corpus has been imported, no bilingual scoring has occurred, and S5/S8/S9 language quality remains unmeasured. Auralis has passed two worker-subprocess crash paths: a mock-based test repairs a lagging host counter and permits a new pending attempt; a [checked-model test](../eval/experiments/2026-09-25-managed-worker-crash.md) verifies model-child cleanup and full resume of the remaining block through both real SQLite files. Neither launches a native Tauri desktop process.

The Auralis subtitle workspace now refreshes its source/result comparison when the run panel observes a changed ready selected result. Focused component tests pass for the notification and reloaded comparison. The panel still polls rather than subscribing to progress events. A native E2E runner verified the underlying React actions and command path with one checked model; interactive user-operation and crash/restart evidence remain open.

A [deterministic two-database crash test](../eval/experiments/2026-09-25-result-gap-recovery.md) now covers the other publication boundary: a worker dies after Translate commits a validated result but before Auralis stages output. Startup publication recovery stages the missing copy once, leaves it unselected while pending, and the outbox selects it after another host database reopening. This uses a mock HTTP model and does not establish native Tauri crash behavior or linguistic quality.

Auralis SQLite schema v9 now stores each Translate result revision in its publication row. A same-run, same-link staged edit blocks automatic or direct selection of the older model result until the newer artifact is ready. A failed newer publication does not silently fall back to the earlier copy. Existing v8 publications receive revision 1 during migration. The local storage regression passes; a concurrent desktop process crash remains unverified.

Startup recovery now checks the latest Translate result ID on every link with an active run or selected result. An earlier pending or ready publication cannot hide a newer committed manual edit. A two-database integration test covers edit recovery before and after first selection, publication finalization, and an unchanged original. Native desktop process interruption remains open.

## Managed desktop admission slice

Auralis now exposes `start_translation_run_cmd` for a prepared project run. The application checks the link and Translate phase, acquires one managed runtime lease, then creates and executes the host job. The runtime requires a checked frozen profile and matching local GGUF digest, starts a private loopback `llama-server`, verifies the reported model/runtime identity, and owns the child for the attempt. A successful result is staged for the existing artifact outbox; the project selects it only when ready. The desktop displays committed block counts, start/resume, and a pending pause distinct from an acknowledged pause. When `translation-runtime.json` is absent from Auralis application data, the start command returns an unavailable-runtime error before creating a job.

`task rs:test:application` passed the application tests, including resource rejection with zero host jobs. `task rs:test:translate` passed the adapter tests, including rejection of unchecked profiles, changed profile hashes and mismatched model files before process start. `task rs:clippy`, `task fe:typecheck`, `task fe:lint`, `task q:ipc-contract`, and focused frontend component tests passed. An opt-in local test then ran a checked managed llama.cpp child through both real SQLite files, committed one Chinese → Russian result, finalized its separate output artifact, and confirmed the external original remained unchanged. The managed-process smoke passed in 172.30 seconds; the full two-database test passed in 249.11 seconds. Both tests require the installed pinned model and runtime and are excluded from default CI. A later native Tauri E2E independently verifies desktop invocation. These checks do not prove whole-desktop kill/restart recovery, broader subtitle behavior, or bilingual quality. See [host jobs](architecture/006-host-translation-jobs.md) and the Auralis translation setup document for the current configuration contract.

## Reproduce the current path

S7 local-file entry is implemented in Auralis: the desktop picks an SRT/VTT file, the backend validates format and filename, inspects only declared text slots, stages a separate managed original, verifies the staged size/digest, and commits artifact finalization through the outbox. A ready copy can be selected to freeze a Chinese → Russian run with stable retry IDs. A two-database test verifies import, outbox readiness, inspection, Translate registration, malformed-input rejection and unchanged external bytes. Component tests cover picker cancellation, unsupported extension, pending artifact display and ready-source run preparation. This does not execute inference or establish release support.

From this repository root:

```sh
task check
task inspect -- crates/auralis-translation-formats/tests/fixtures/plain.srt
task cli -- template crates/auralis-translation-formats/tests/fixtures/plain.srt translations.json
```

Edit each `lines` value in `translations.json` while keeping the IDs and number of lines. Then run:

```sh
task cli -- render crates/auralis-translation-formats/tests/fixtures/plain.srt translations.json translated.srt
```

With a separately started loopback llama-server and a validated profile manifest, the first durable CLI path is:

```sh
task cli -- translate source.srt state-dir models/manifests/hy_mt2_1_8b_q4_k_m.experimental.json http://127.0.0.1:18080/ translated.srt
task cli -- translate-vtt source.vtt state-dir models/manifests/hy_mt2_1_8b_q4_k_m.experimental.json http://127.0.0.1:18080/ translated.vtt
task cli -- resume state-dir RUN_ID models/manifests/hy_mt2_1_8b_q4_k_m.experimental.json http://127.0.0.1:18080/ translated-after-resume.srt
task cli -- status state-dir RUN_ID
task cli -- diagnostics state-dir RUN_ID
task cli -- pause state-dir RUN_ID
task cli -- edit state-dir BASE_RESULT_ID models/manifests/hy_mt2_1_8b_q4_k_m.experimental.json edit.json corrected.srt
task cli -- doctor models/manifests/hy_mt2_1_8b_q4_k_m.experimental.json path/to/Hy-MT2-1.8B-Q4_K_M.gguf
task cli -- translate-glossary source.srt state-dir models/manifests/hy_mt2_1_8b_q4_k_m.glossary.experimental.json glossary.json http://127.0.0.1:18080/ glossary-translated.srt
```

The first command prints and flushes `translation_id` and `run_id` after recording the run, so keep the `run_id` if inference stops. During inference, stderr reports `run_id=... saved_blocks=N/M` after loading valid checkpoints and after each newly committed block. `pause` works from another process while translation runs; `status` reports `pause_requested=true` until the worker acknowledges it. `resume` can also re-export an already validated result without contacting the server. The fixed durable CLI language pair is Chinese → Russian; no Japanese capability is claimed.

For `edit`, create a UTF-8 JSON file such as `{"schema_version":1,"segment_id":1,"lines":["Corrected Russian line."]}`. Use the actual Russian correction and keep the source segment's line count. The command rejects a stale base result, invalid SRT text, a changed managed original or profile, and an existing output. It stores a new result revision before exporting; if file publication fails, `resume` can re-export the latest verified result. Earlier result IDs and output files remain unchanged.

To require server preflight on a new run, use `models/manifests/hy_mt2_1_8b_q4_k_m.checked.experimental.json` in place of the older experimental profile. It pins llama.cpp b10977, a 2048-token minimum context, model size, and model hash. This streams the local GGUF through SHA-256 before an attempt begins; on the debug-build smoke it added roughly a minute. Keep the original profile file for an existing run because the profile fingerprint is frozen. The checked profile does not manage the server process or prove the bytes held in memory.

These commands use `create_new` semantics: choose paths that do not exist. The default SRT and WebVTT inspection policies each permit up to 16 MiB of source bytes, 100,000 cues, and 16 KiB per line; callers may pass a separately validated policy to the library. The fixture is synthetic and its provenance is recorded in `crates/auralis-translation-formats/tests/fixtures/LICENSE.md`. The last verified `task check` passed formatting, Clippy, and 75 behavior tests, including CLI process, doctor SHA checks, checked-server preflight and hash rejection, malformed provider output, bounded context and scoped glossary protocol, immutable glossary resume, advisory glossary warnings through SQLite reopen, local HTTP protocol, SQLite v1→v3 migration, source-map persistence including absent WebVTT cue IDs, checkpoint and failed-commit progress, pause/resume, bounded retry with persisted attempt count, persisted warnings, versioned manual edits, complete SRT and WebVTT reconstruction, stale output-temporary cleanup, strict WebVTT extraction and copy/rejection cases, manual and durable WebVTT CLI round trips, model-contract WebVTT acceptance/rejection, and corrupt-hash handling. The CLI pause and resume tests use a deterministic mock HTTP model and do not establish real-model quality. See the current command output before reporting a later gate as complete.
