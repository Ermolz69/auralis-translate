# Source name registry v1

Date: 3 October 2026. NAME-01 is a bounded engineering/development prerequisite
of CTX-03, EVAL-04 and LONG-04. It does not complete those tasks or G3–G5.

NAME-02 adds [admission v1](../reference/name-proposal-admission-v1.md).
The NAME-01 proposal screen is rejected: old proposal profiles are historical
identities, not permission for new unguarded inference. A fresh guarded profile
retains raw/parsed candidates and explicitly rejects active proposals before
checkpoint because source-aware identity/action verification is unavailable.

Translate SQLite owns immutable registry revisions under an existing translation
snapshot (and its external project identity). Source digest, scene map, extraction
policy and revision are part of the identity. Each entity stores Chinese surface,
possible addresses/aliases, exact segment/line/UTF-8 byte occurrences, scene scope,
optional Russian proposal, proposal provenance, review state and revision.
Candidates are extracted from Chinese source only; references are never inputs.

Extraction is deliberately conservative: explicit self-introductions and bounded
surname/address patterns produce candidates, then exact source occurrences are
recorded. Matching surnames, similar spellings and possible aliases do not merge
entities. Scene-separated identical surfaces remain separate and need review.
Product/place words and metalinguistic/quoted uses are negative controls, not
evidence of a person. This lexical extraction has incomplete recall and cannot
prove identity. Unresolved links remain independent `needs_review` records.

Algorithm/model proposals always remain unapproved. Human approval requires
explicit reviewer and evidence identities. The experimental v8 registry extension
has a separately pinned policy hash and manifest; existing v8 request bytes and
approved-term APIs remain unchanged. Only exact occurrences in current target
slots activate proposals. Neighbor-only names never enter a target hint. Scene
and source checks precede selection; token preflight includes the rendered hints.
Context trimming and slot splitting select hints again for the remaining slots.

Registry revisions are immutable and append transactionally with optimistic head
checks. Runs bind the exact revision/digest and refuse resume when the current
registry head differs. Accepted checkpoints/results remain immutable; changed
decisions require a fresh run. An empty registry still has a revision identity.
Raw rejected model responses use the existing inference journal. No incomplete
subtitle result is published. Project cleanup cascades the owned registry.

Deterministic checks establish extraction, isolation, versioning and durability.
A frozen paired real-model development screen separately measures name spelling
consistency and source meaning. A failed screen stops advancement to a natural
long-file run. AI review is labelled; independent Chinese–Russian review remains
unavailable. No human-approved name, language gate or complete Goal is claimed.
