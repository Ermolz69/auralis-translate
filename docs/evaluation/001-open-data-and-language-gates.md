# Open data and language evaluation protocol

Status: candidate sources and proposed protocol, 25 September 2026. The official FLORES-200 archive has been acquired and hash-verified locally for **auxiliary sentence-level model comparison**; its [pinned manifest](../../eval/corpora/flores200-archive-b8b0b767.json) and [acquisition record](../../eval/experiments/2026-09-25-flores200-acquisition.md) contain reproducible provenance. **No release subtitle corpus has been acquired, cleared item by item, aligned, or reviewed. No Chinese or Japanese language gate is passed.**

Historical data protocol: this document records the original reviewer-based route and its source discoveries. The owner's current translator-only route is [published-reference review v2](011-published-reference-review-v2.md); it does not require recruiting a reviewer. Earlier candidate findings and limits below remain evidence, not current acceptance instructions.

The owner confirmed there is no existing approved Chinese/Japanese subtitle set or bilingual reviewer. The working data choice was: use the already pinned FLORES-200 snapshot for model diagnostics, optionally add an attributed Tatoeba export for short-utterance probes, and build separate real-subtitle Chinese and Japanese scene corpora from individually cleared timed-text sources. The [Tatoeba reuse guide](https://en.wiki.tatoeba.org/articles/show/using-the-tatoeba-corpus) permits text reuse with attribution under CC BY 2.0 FR; its sentence pairs have no subtitle timing or scene context. Commons timed-text pages are discovery leads until each source and reference passes the item-level rights and alignment checks below.

## Acquisition and provenance

1. Build a source inventory before importing third-party text. For each item record `dataset`, `source_url`, `media_url` if any, exact page/release revision, retrieval date, original SHA-256, source/target language and script, attribution, license identifier and URL, modification/ShareAlike obligations, and permitted internal/public use. Keep source and Russian reference rights separate.
2. Reject an item when rights are unclear, it is a machine-generated translation presented as a human reference, its language cannot be verified, the source has unsupported syntax for the intended gate, or a timing/source mismatch cannot be resolved. Do not copy such text into the repository. Record rejection reasons without copying content.
3. Preserve an unmodified downloaded source revision. Use the strict inspector to select supported text slots and hash exact source bytes. Exclude non-dialogue cue types deliberately and record exclusions. Never normalize the source in place.
4. For the product corpus, a bilingual reviewer writes or verifies a Russian reference **from the Chinese or Japanese source with scene context**, retaining source cue IDs, order, and timing. A pre-existing Russian track can provide context but must be aligned and checked; it is not automatically a gold reference.
5. Keep licensed corpus files and attribution in a separate data location/repository with its own license and NOTICE, outside the source-code tree, until redistribution terms have been checked. The code repository may keep only a manifest of links, hashes, and aggregate results. If a source requires ShareAlike for derivative references, publish those references under compatible terms or keep the item out of a distributable corpus.
6. Freeze a versioned manifest with content hashes, split membership, cue-level tags, reviewer identities or pseudonyms, review date, and exclusion rules. A change to source, reference, split, or rubric increments the corpus version and requires a new report.

Recommended manifest fields: `corpus_version`, `item_id`, `source_url`, `source_revision`, `source_sha256`, `reference_sha256`, `media_url`, `source_language`, `script`, `target_language`, `format_subset`, `license_source`, `license_reference`, `attribution`, `allowed_uses`, `scene_id`, `split`, `cue_ids`, `tags`, `alignment_review`, and `review_state`. A manifest entry does not imply clearance until `review_state=approved`.

## Frozen split and coverage

Follow the [product plan](../PRODUCT_PLAN.md#15-evaluation-and-release-gates): target roughly **20–30 scenes / 500 cues per language**, with about **200 development cues and 300 held-out cues**, split by video/scene rather than random cue. This is a collection target, not a claim that such data already exists. Keep all material from one source video in a single split; deduplicate near-identical text against development and public benchmark sets. Do not tune prompts, glossary, decoding, or model choice on held-out scenes. The final holdout may be evaluated once per frozen release candidate; after using it to tune a profile, retire it into development and acquire a new holdout.

Record coverage for dialogue turns, names and terminology, idioms, negation, numbers, split sentences, speaker changes, overlaps, multiline cues, protected tokens, and manual versus ASR-origin text when rights and format support permit. Chinese should include simplified and traditional text if that support is advertised. Japanese needs explicit honorific, ellipsis, name-reading, and register cases. Report missing strata honestly rather than filling them with unrelated sentence data. Unsupported markup belongs in a rejection corpus, not in the linguistic denominator.

## Run and review protocol

1. Pin candidate model bytes/hash, runtime build, prompt/template, profile version, glossary, context policy, parser version, OS, CPU/GPU, and corpus version. Run the complete file-to-file path on untouched input. Save result IDs, diagnostics, output hashes, per-cue text, wall time, cold-start time, peak RAM/VRAM, and attempt counts. A model-only call is supplementary evidence.
2. Machine checks first: exact expected IDs and text-slot count; source byte hash unchanged; cue order, timing, supported settings, protected bytes, and source-line policy preserved; output reparses; no partial publication. Structural failures block that output and count in G1/G8. Report how many source files were rejected before inference and why.
3. For each accepted result, give a reviewer fluent in the **source language and Russian** the original source, neighboring cues, scene/video when permitted, machine output, and reference. Blind model/profile identity during comparative review. Rate adequacy per cue on 1–5; record fluency, names/terms, omissions/additions, negation/numbers, cue-local meaning, register, and readability separately. Mark critical errors explicitly: meaning reversal, wrong person/action/time, dangerous misinformation, or an omission that materially changes the scene. Use a second bilingual reviewer to adjudicate disputed or critical cases and record the resolution.
4. A natural translation may differ from the reference. Score meaning against the source, not exact wording. Use automatic metrics only for triage/comparison; never use BLEU/chrF or an LLM judge alone to pass G3/G4. Treat warning-free output as unreviewed until human assessment.
5. Report by language **and** by script/scene/format/profile. Calculate G3 as `(number of reviewed eligible cues scored >= 4) / (number of reviewed eligible cues)`; G5 as `(approved terms correctly rendered) / (applicable approved-term occurrences)`, allowing agreed Russian inflections. Publish numerator, denominator, confidence limitations, exclusion reasons, and critical-error list. A zero critical count on a 300-cue holdout is evidence for that set only.
6. Compare candidates on the same frozen development scenes with their correct model templates. After choosing one profile, run the untouched holdout and measure the [G1–G9 gates](../PRODUCT_PLAN.md#15-evaluation-and-release-gates): structure, meaning (at least 95% at adequacy ≥4/5), no unresolved critical holdout errors, terms (at least 98%), declared-hardware resources, crash/resume, export in a target consumer, and clean offline installation. Set numeric performance targets only after profiling target hardware.

S5 can use the pinned FLORES corpus as auxiliary model-selection evidence and the first reviewed subtitle scenes. Use `dev` for prompt/profile exploration; treat public `devtest` as a repeatable comparison set, **not** as the frozen release holdout. Keep the archive outside Git; `task eval:flores:verify` checks archive and selected file hashes, expected language files, metadata header, and aligned row counts. `task eval:flores:compare -- SPLIT LANGUAGE ROW_IDS CHECKED_PROFILE SERVER_URL OUTPUT_JSON` runs at most 32 specified one-based rows through a verified local prompt-v1 model, saves source/reference/candidate triples only under the ignored corpus cache, and does not calculate a quality score. The profile and loaded model hash, runtime build, corpus hash, split, row IDs, and per-row warm-call time enter the report. A [two-row live smoke](../../eval/experiments/2026-09-25-flores200-provider-smoke.md) exposed a Japanese-source/Russian-reference currency discrepancy, reinforcing source-aware human review. S8 requires a **separate licensed Chinese scene holdout and bilingual review** in addition to technical release gates. S9 repeats the full process on Japanese and reruns Chinese regression; Japanese does not inherit the Chinese score. Auralis labels structurally valid but uncertain output **Needs review**, never “quality passed” from an automated heuristic.
