Распознанные денежные выражения заменяются маркерами только в запросе к модели. Адаптер проверяет их число и порядок, затем восстанавливает точные суммы и валюты из исходника. Настоящие шекели, шиллинги, доллары, евро, иены, рубли и гонконгские доллары сохраняются. Исходный файл неизменен.

Ограничения: общий смысл и грамматика всё ещё требуют проверки — например, в контроле сдачи модель пишет «Ищу тебя» вместо «Твоя сдача». Защита охватывает ограниченные формы чисел и денежного контекста; неизвестные формы переводит модель. Старый desktop package продолжает выбирать v1; v4 включается явно для нового CLI-прогона.

Как работает этот прогон

  1. 01

    Проверить SRT

    20 однострочных реплик, UTF-8, CRLF. Тайминги искусственные: по 4 секунды на реплику. Исходник остаётся неизменным.

  2. 02

    Подготовить модель

    Проверить размер и SHA-256 GGUF, имя модели и сборку llama.cpp. Локальный сервер уже загружен; скачивания нет.

  3. 03

    Перевести и сохранить

    Один HTTP-запрос на строку, без соседнего контекста и глоссария. План: 3 блока, по 8 / 8 / 4 реплики. Проверенные блоки сохраняются в SQLite.

  4. 04

    Создать отдельный файл

    Повторный парсинг сверяет порядок, ID, тайминги и защищённые байты. После остановки сервера resume воспроизводит каждый результат байт в байт.

Границы сравнения

  • Три свежих состояния SQLite, один загруженный сервер. Первый файл следует за readiness; остальные используют тот же рантайм. Холодный дисковый кэш не обеспечивался.
  • Прокси на loopback фиксирует время до полного тела ответа. Служебные /props и проверки GGUF в замер отдельного запроса не входят. Токенные времена сообщает сам llama.cpp; кэш prompt может влиять на повторения.
  • Браузерное получение Google выполнялось во время локальных прогонов. Машина не была изолирована; это измеренный пример, а не обещание скорости на другом ПК.
  • Обработка строго китайских реплик: CLI фиксирует zh → ru. Японский путь, сцены с контекстом, глоссарий и реальные таймированные субтитры этим отчётом не проверены.
  • Первый запуск в sandbox остановился до запуска модели из-за EPERM при создании дочернего процесса. Затем задача успешно повторена. Это отказ окружения, 0 запросов, а не скрытая неудачная генерация.
